the M8.5 modern-layout-resilience addendum. Story-level detail lives in
`doc/milestones/milestone8.md`; these are the work items archived from

## Archived from `doc/TODOs.md` on 2026-07-26

- [x] **[M8 P0] T-COOKIE-NAV-INITIATOR-1: Thread The Navigation Initiator Into The Cookie Context** — DONE 2026-07-21. `NavigationSource` (User vs Document) added at the Tab seam; `Tab::initiator_host_for` reads the current document's host BEFORE `begin_navigation_session` switches it, and passes it as `DocumentRequest::initiator_host`. - [x] **[M8 P0] T-DOC-ERROR-LOST-1: Failed Documents Dropped Their NetworkError** — FIXED 2026-07-21 (found writing 8.3.1's tests). `ResourceUpdateProcessor::process_update` short-circuited on `!update.success` and returned before recording the navigation result, so `BatchResult::document_error` stayed `None` for every failed document. A redirect loop was therefore indistinguishable from a blank page, and story **8.3.2's error pages would have had nothing to render**. A failed document now reports url/effective_url/error while deliberately not setting `ready`. Pre-existing and wider than redirects; regression covered by `RedirectChain.test.cpp`.

- [x] **[M8 P1] T-STUB-FALLBACK-MASKS-ERRORS-1: Definitive Failures Retried Against The Stub Network** — FIXED 2026-07-21 (same session). The document path treated any empty-bodied response as "curl gave up, try the stub", which for a redirect loop meant answering with a demo page instead of the error. Redirect-policy failures are definitive answers about a URL and now surface directly. *(Narrower than it looks: only redirect errors are special-cased. The broader question of which failures should fall back to the stub at all is worth revisiting in 8.3.2, where the error-page path gets designed.)*

- [x] **[M8 P1] T-COOKIE-REDIRECT-CONTEXT-1: Recompute The SameSite Context Per Redirect Hop** — DONE 2026-07-21, completing story 8.1.3. The hop that issued a redirect becomes the next hop's initiator, so a chain that crosses sites makes every later hop cross-site; `safe_method` follows the rewrite, so a 302 that turns POST into GET makes the next hop safe for Lax while a 307 that preserves POST does not. Tests in `RedirectChain.test.cpp`.

- [x] **[M8 P0] T-NET-SCHEME-CONFINEMENT-1: Engine Would Fetch file:// URLs** — FIXED 2026-07-21 (found answering "could malicious JS read the cookie file?"). JS itself cannot: quickjs-libc is not initialized, so there is no filesystem API in the script environment. But the *navigation* path could: `file://localhost/C:/…` parses cleanly (only the hostless `file:///…` form was rejected, by accident), `resolve_url` passed it through, `RedirectPolicy` followed it, and libcurl serves `file://` by default with no `CURLOPT_PROTOCOLS` restriction. A malicious page could link — or a malicious server 302 — to the cookie jar and have it rendered as a document; with M9's `fetch` that becomes exfiltration. Now blocked in three places: `Core::is_fetchable_web_url` (http/https only) gates `ResourceLoader::navigate` and `RedirectPolicy::decide`, and curl is pinned to http,https for both requests and redirects. Tests in `RedirectChain.test.cpp`.

- [x] **[M8 P0] T-NET-REFERRER-1: Send A `Referer` Header (default referrer policy)** — DONE 2026-07-22 (HN sidetour). We sent no `Referer` on any request, ever; HN's write endpoints treat a refererless cross-check as abuse and answer the comment POST with a 6-byte `429 "Sorry."`, so "add comment" never reached the login/register page — a North-Star blocker. `Core::compute_referrer_header` (`src/core/net/Referrer.cpp`) implements the browser default **strict-origin-when-cross-origin**: same-origin sends the full URL minus fragment, cross-origin sends the origin only, an https→http downgrade sends nothing, and a user-initiated navigation (empty initiator) sends nothing. Threaded as `DocumentRequest::initiator_url` (Tab captures the current document URL before the session switches, same seam as `initiator_host`) and as `RedirectChain::referrer_source`, recomputed per hop at the `send_request` choke point exactly like the Cookie header, so subresources and redirect chains re-apply the policy against each hop's target. Tests: `Referrer.test.cpp` (policy) + `ResourceLoader.test.cpp` (same-origin/cross-origin/user-initiated/subresource actually attach it). **Known gaps (deferred here, not scheduled):** source-URL userinfo is not stripped, and a page's `Referrer-Policy` header / `<meta name="referrer">` / `rel="noreferrer"` are not honored — the default policy is applied unconditionally. *(A realistic `User-Agent` may be a second HN write-path gate; `Hummingbird/0.2` passes HN's GET, so Referer was the first-order cause — revisit UA only if a POST still 429s.)*

- [x] **[M8 P0] T-NET-IDENTITY-1: Per-Origin Browser Identity (Transparent / Compatibility)** — DONE 2026-07-22 (HN sidetour, with Codex's controlled-test diagnosis). Referer/Origin/cookies were all correct, yet HN kept answering the comment/login POST with `429 "Sorry."`. Controlled tests (same IP, varying only the UA) proved it is HN's **canonical-UA anti-crawler rule**, not rate limiting or CSRF: a bare `Hummingbird/0.2` → 429, *any* noncanonical legacy suffix (incl. `… Hummingbird/0.2 Chrome/…` and even Vivaldi's documented suffix) → 429, canonical Chrome UA → 200, canonical UA + truthful `Sec-CH-UA: "Hummingbird"` → 200. So an honest token *embedded in the UA string* is the worst option. Implemented two identity modes where **only the legacy `User-Agent` differs**; `Sec-CH-UA`/`-Mobile`/`-Platform` are identical, truthful (`"Hummingbird";v="0", "Not_A Brand";v="99"`, never `"Chromium"`), and secure-context-only. `Core::BrowserIdentity` (pure header builder) + `Core::IdentityPolicyStore` (per-origin mode, default Transparent, persisted TSV of only the Compatibility origins, shared per profile like the cookie jar). Attached at the `ResourceLoader::send_request` choke point per **target** origin, recomputed per redirect hop; `CurlNetwork` no longer hard-codes a UA (engine owns identity end to end). User flips a site with **Ctrl+Shift+U** (`BrowserApp::toggle_active_site_compatibility` → reload); the choice persists across restart. Tests: `BrowserIdentity.test.cpp`, `IdentityPolicyStore.test.cpp`, `ResourceLoader.test.cpp`. Also added response-header/body logging on any HTTP error in `CurlNetwork` (shows `Retry-After` etc.) and a per-POST identity/CSRF log line. **Default stays honest; Compatibility is opt-in per site, never automatic, never applied to a POST silently.** *(Deliberately NOT a hard-coded HN exception — any site the user hits can be flipped.)*

- [x] **[M10 P3] T-NET-IDENTITY-PLATFORM-1: Make Identity Platform Tokens Track The Build Target** — DONE 2026-07-22 (commit 593c6bb), pulled forward from M10 because shipping a dishonest OS token contradicts the Transparent default. `Core::BrowserIdentity` selects the UA parenthetical and `Sec-CH-UA-Platform` at compile time per target: `_WIN32` → `Windows NT 10.0; Win64; x64` / `"Windows"`, `__linux__` → `X11; Linux x86_64` / `"Linux"`, `__APPLE__` → `Macintosh; Intel Mac OS X 10_15_7` / `"macOS"`; Compatibility mode's Chrome-shaped UA uses the same OS token. Tests stay platform-agnostic (they assert the product/brand tokens, not the OS). *(Checked off 2026-07-24 in the pre-merge review — the fix shipped but the box was never ticked.)*; Goal: stop hard-coding the Windows OS token in the User-Agent / `Sec-CH-UA-Platform`; Scope: `Core::BrowserIdentity` hard-codes `Windows NT 10.0; Win64; x64` and `"Windows"`; derive these from the build/runtime platform (and decide what Compatibility mode should claim on Linux/macOS) so a non-Windows build does not misidentify its OS; Acceptance: a Linux build sends a Linux platform token in Transparent mode; Tests: per-platform identity tests. *(Filed 2026-07-22; low priority while Windows is the only target, but it is a correctness gap the moment another platform ships.)*

- [x] **[M8.5 P2] T-COMPAT-WARN-SUMMARY-1: Count Repetitive Compatibility Warnings** — DONE 2026-07-23. Expected compatibility gaps now use a document-owned `CompatibilityWarnings` counter instead of flooding the operational log: the first unsupported font-family fallback warns immediately, repeats increment a structured `{category, detail}` entry, and navigation/shutdown prints a count-ranked summary (top 20) only when repeats were suppressed. - [x] **[M8.5 P1] T-CSS-REPLACED-PERCENT-SIZE-1: Percentage/`em`/`rem` Width & Height On Replaced Elements** — DONE 2026-07-23; corrected 2026-07-24. `ReplacedElementUtils` now takes an optional containing-block width/height and resolves a percentage `LengthValue` against it (`resolve_length`). `RenderImage`/`RenderSvg::layout` pass `bounds` as the basis, gated on a positive extent, mirroring `BlockBox::resolve_height_constraint`. The inline-measure width path keeps its bounded bare-magnitude behavior until its containing width is plumbed, while an indefinite percentage **height** correctly computes to `auto` and follows the media's intrinsic ratio instead of becoming a literal 100px. Replaced layout now also treats an existing `ComputedStyle` as authoritative: HTML `width`/`height` presentational hints enter the cascade in `StyleDefaults`, so layout must not re-read a raw natural-dimension attribute after author CSS such as `height:auto` has overridden it. Tests: `ReplacedSizingTest.*` (percent width/height resolve, px unaffected, no-basis width fallback, indefinite height → auto, CSS auto overrides HTML dimensions, unstyled fallback) + `StyleEngineTest.CssAutoHeightOverridesHtmlPresentationalHint` + `BlockBoxLayoutTest.ReplacedPercentWidthResolvesAgainstContainingBlock`. Demo: example.dev/layout icon row and auto-height/responsive images. Goal: size an `<img>`/SVG from a non-px CSS length instead of falling back to its intrinsic size; Scope: `ReplacedElementUtils::resolve_dimension` (`src/layout/geometry/metrics/ReplacedElementUtils.h`) resolves a styled dimension through `raw_px`, which reads only the **px** part of a `LengthValue` — so `width:100%` / `2rem` / `3em` on a replaced element resolves to ~0 and the code falls through to `intrinsic_value` (the media's natural size). Seznam sizes its service icons as a percentage of a fixed-size flex cell, so they balloon to the SVG's intrinsic ~200px. Pairs with T-CSS-OBJECT-FIT-1 — percentage sizing gives the box its size, object-fit fits the pixels inside it; both are needed for the icons. Contained: one resolver, no layout-model change.)*

- [x] **[M8.5 P1] T-CSS-OVERFLOW-CLIP-1: Paint-Time Clip For `overflow: hidden` / `clip`** — DONE 2026-07-23. `RenderObject::paint` wraps the child-paint loop in `push_clip(border-box)` … `pop_clip()` when BOTH `overflow_x`/`overflow_y` are `Hidden` (the `overflow:hidden` shorthand). Single-axis hidden is deliberately not clipped (a rectangular clip can't leave the other axis unbounded, and over-clipping the common `overflow-x:hidden` idiom would hide wanted content); Scroll/Auto are not clipped either — without scroll offsets (M10) that would hide unreachable content. The box's own border/background paint before the clip. Tests: `OverflowClipTest.*` (clips to border box on hidden; no clip on visible; no clip single-axis) + `TestGraphicsContext` now records clip calls. Demo: example.dev/layout clip card. Goal: stop a child that overflows an `overflow:hidden` box from painting across the rest of the page; Scope: `ComputedStyle::overflow_x`/`overflow_y` already exist and the DisplayList already has `PushClip`/`PopClip` (`src/renderer/DisplayList.h`), but block/flex boxes never emit a clip, so an oversized child bleeds over its neighbours (seznam's fixed-size cards spill their contents over adjacent text — visible as stacked/overlapping runs in the screenshots). During paint, wrap a box whose computed overflow is `hidden`/`clip` in `push_clip(border-box)` … `pop_clip()`; **clip only** — no scroll offset, no scrollbars, no hit-test change; Acceptance: a child larger than an `overflow:hidden` parent is visually clipped to the parent's box; Tests: display-list/paint clip tests. *(Filed 2026-07-23. Deliberately the cheap half of M10's "Overflow + Scrolling v2": real scroll containers, `overflow:auto/scroll` offsets, and scrollbar hit-testing stay in M10 — this only stops the bleed. Infra already present, so it's wiring, not new machinery.)*
